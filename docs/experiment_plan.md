## 4. Процедура проведения эксперимента

### Подготовка
1. Скопировать нужный файл препятствий в `obstacles.txt`:
   ```bash
   cp obstacles_light.txt obstacles.txt   # лёгкий сценарий
   cp obstacles_heavy.txt obstacles.txt   # тяжёлый сценарий
   rm obstacles.txt                       # без препятствий
   ```

2. Запустить Gazebo-мир:
   ```bash
   roslaunch px4 multi_uav_mavros_sitl.launch
   ```

3. Запустить эксперимент:
   ```bash
   # Пример: APF + light obstacles, 3 дрона
   python3 launch_experiment.py --algo apf --n 3 --bg
   ```

### Имитация потери дрона
Во время полёта принудительно "убить" процесс одного дрона:
```bash
# Найти PID процесса
ps aux | grep apf_drones

# Остановить дрона 1 (например)
kill <PID_uav1>
```
Или через ROS:
```bash
rostopic pub /uav1/mavros/state mavros_msgs/State "connected: false"
```

### Сбор данных
После завершения миссии:
```bash
python3 plot_metrics.py --dir . --save
python3 plot_trajectories.py --dir . --save --field_len 60 --field_wid 30 --height 5
```

## 5. Метрики для сравнения

| Метрика | Обозначение | Единица | Как считается |
|---|---|---|---|
| Ошибка строя | formation_error | м | Евклидово расстояние до target waypoint |
| Время миссии | mission_time | с | От MISSION_START до MISSION_END |
| Пройденный путь | path_length | м | Сумма перемещений по XY |
| Покрытие поля | coverage_pct | % | n_drones * stripe / field_wid * 100 |
| Межкоптерное расстояние | nearest_neighbor | м | До ближайшего соседа |
| Средняя скорость | velocity | м/с | path_length / mission_time |
| Энергия (proxy) | energy | м²/с² | integral(v^2 dt) — добавить в plot_metrics |
| Cross-track error | cross_track | м | Боковое отклонение от идеальной траектории |

## 6. Ожидаемые результаты (гипотезы)

| Гипотеза | Ожидание |
|---|---|
| H1 | Hard-code имеет минимальное formation_error при отсутствии препятствий, но деградирует при потере дрона |
| H2 | APF+Lanes обеспечивает наилучшее покрытие поля за счёт удержания полос |
| H3 | Boids демонстрирует наибольшую гибкость при плотных препятствиях, но с большим formation_error |
| H4 | APF показывает баланс между formation_error и устойчивостью к препятствиям |
| H5 | При потере дрона адаптивные алгоритмы (APF, APF+Lanes, Boids) восстанавливают покрытие, hard-code — нет |

## 8. Сокращённый вариант (если не хватает времени)

Если 72 запуска — слишком много, можно сократить до **36 запусков**:
- Hard-code: только без потери дрона (6 -> 3 комбинации x 3 = 9)
- APF, APF+Lanes, Boids: полный набор (18 комбинаций x 3 = 54)

Или до **24 запуска**: по 1 прогону каждой комбинации.
